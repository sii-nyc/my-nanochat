# Tokenizer：BPE 原理与对比实验

**记录日期**：2026-10-01（回顾 2026-09-02 至 2026-09-03 的工作）

**状态**：已完成 tokenizer 部分的理解，并开展了一轮分词器对比实验。

## 目标与结论

这一阶段的重点是理解 nanochat 的分词器为什么这样设计，以及它如何从训练数据变成模型可用的 token ID。我们梳理了 ClimbMix 文本从 Parquet 文件进入训练流程的路径，理解了按文档截断和累计字符数取样的方式；随后沿着预切分、UTF-8 字节基础词表、频繁字节对合并，直到加入特殊 token、构造编码器和保存词表，走通了 byte-level BPE 的训练与使用流程。也理解了 token 原始字节长度缓存为何用于后续模型的 BPB 评测。这部分原理和流程见[阅读笔记](../../reading_notes.md)。

在理解流程的基础上，我们设计了两个对比方向：固定 **32K 词表**，比较标记为 **1B、2B、3B 训练字符**的 tokenizer；固定 **2B 训练字符**，比较 **16K、32K、64K 词表**。定量上，用相同文本的 **BPT（UTF-8 字节数 / token 数）**比较切分效率，样本包括新闻、韩文、代码、数学、科学文本，以及当前数据目录中训练集和验证集各自的首个 row group。定性上，用同一段包含中英文、韩文、数字、代码、空白和 Unicode 字符的文本观察 token 边界与字节片段。GPT-2 和 GPT-4 tokenizer 被放入报告作为参照，但它们的词表和训练条件不同，不属于上述控制变量实验。为保存多个实验结果并直观查看切分，我们也增加了具名 tokenizer、Markdown 报告和离线网页查看器；用法与完整数据保存在[历史实验记录](../../experiments/tokenizer/2026-09-initial.md)。

这轮样本的主要观察是：固定 32K 词表时，`climbmix-val` 样本 BPT 从 1B 的 **4.6649** 到 2B 的 **4.6653**，3B 在四位小数下仍为 **4.6653**；固定 2B 字符标签时，16K、32K、64K 词表依次为 **4.3757、4.6653、4.8526**。在本批样本中，改变词表大小的影响比继续增加训练字符数更明显。定性切分也显示，大词表可以合并更多完整词片段，但中韩文字符仍可能被拆成单独无法解码的字节片段；总体 BPT 接近的词表也可能有不同的局部切分。

这些结论只适用于已经测试的文本。训练规模来自实验文件名，原始运行记录未提供实际读取字符数；`climbmix-val` 也只取了一个 row group。BPT 衡量平均每个 token 承载多少字节，不能单独证明下游语言模型效果，也不足以决定未来基础模型使用哪一个词表。
